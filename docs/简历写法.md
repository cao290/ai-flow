# 简历写法与投递建议

## 一、简历条目（直接抄，按需调整）

### 版本 A：偏 AI 工程师 / Agent 应用岗（推荐主线）

> **ai-flow · AI 工具流编排器** ｜ 独立项目 ｜ Python/Node.js ｜ 2026.10
>
> 针对本机 12 个 MCP 服务、223 个工具的编排痛点，设计并实现统一工作流编排层，
> 将「技术调研」等多步骤任务从人工编排 3 步工具调用固化为可声明、可审计的工作流。
>
> - **零依赖实现 MCP 协议栈**：自研 stdio JSON-RPC 2.0 客户端与服务端各一份（约 400 行），
>   不用官方 SDK 以保证零依赖可移植；实现 initialize 握手、tools/list、tools/call、
>   错误码分级与进程级健康管理（超时/崩溃后自动重建，不留僵死进程）。
> - **动态工具索引**：设计统一工具注册表，自动探测运行中的 MCP 服务并建立 223 个工具的
>   统一索引（`服务名::工具名` 限定命名，保留 JSON Schema），采用惰性连接避免无谓进程拉起；
>   新增 MCP 服务零代码改动即可纳入编排范围。
> - **编排引擎**：实现声明式工作流引擎，支持 `${step.field}` 字段级变量渲染、指数退避重试、
>   服务级熔断、optional 步骤语义与逐步审计落盘；错误按可重试性分级，避免盲目重试放大故障。
> - **幂等层**：副作用步骤声明业务键，持久化账本命中即跳过——失败链重跑不重复归档；
>   实测同关键词重跑时归档步骤 1ms 命中，`--force` 可显式绕过。
> - **量化收益**：设计「中转成本」基准（两条路径共享同一份检索输出保证可比）——
>   人工路径步骤间搬运 40.6KB（约 10,791 tokens），编排路径字段级引用降至 19.9KB
>   （约 5,295 tokens），**中转量降低 51%，归档产出逐字节一致**；
>   另用零延迟 mock 隔离测得引擎自身开销每步 0.01–0.4ms（相对下游耗时可忽略）。
> - **验证**：mock MCP 服务隔离外网做端到端自测，34 项断言全覆盖，在无本地配置的干净环境
>   （模拟 CI）同样全过；真实跑通调研/经验沉淀/代码理解/图片理解四条链路，产出自动归档；
>   配 Web 看板（SSE 实时执行进度 + 工具索引 + 历史回放）。

### 版本 B：偏平台工程 / MLOps 岗

> **ai-flow · MCP 工具编排平台** ｜ 独立项目 ｜ Node.js ｜ 2026.10
>
> - 面向 11 个已注册的 MCP 服务（223 个工具）实现统一编排层，零依赖自研 MCP 协议栈（client + server）。
> - 工具注册表采用**动态发现 + 惰性连接**：进程启动时握手探测，写入统一索引与 JSON Schema；
>   工具服务新增/下线自动反映，零代码改动。
> - 编排引擎提供声明式工作流、字段级变量渲染、指数退避重试、服务级熔断、**幂等账本**、
>   **进程自愈**（超时/崩溃自动重建）与全链路审计。
> - **中转成本基准**：对比「工具输出整段过模型上下文」与「编排器字段级引用」两种模式，
>   步骤间搬运量从 40.6KB 降至 19.9KB（**-51%**），产出逐字节一致。
> - 通过 mock MCP 服务解耦下游依赖做端到端自测（34 项断言，Ubuntu + Windows CI 双平台）。
> - 以 MCP 服务形态接入 IDE/Agent 宿主，形成「工具 → 工作流 → Agent」三层调用栈；
>   另配 Web 看板提供 SSE 实时执行观测。

### 版本 C：一行式（简历空间紧张时）

> 开发 AI 工具流编排器：零依赖实现 MCP 协议栈（client + server），动态索引 223 个跨服务工具，
> 提供声明式工作流引擎（重试/熔断/幂等/进程自愈）与 Web 看板，封装为 MCP 工具供 AI 调用；
> 34 项断言自测通过，实测步骤间数据中转量降低 51%。

```
工程能力：Node.js（零依赖服务设计）、Python、JSON-RPC、SSE、REST API 设计、
          错误分级与重试/熔断、可观测性与审计日志
AI 工具链：Claude Code / Cursor / ZCode、视觉模型调用、向量检索与知识库
```

**不要写**「精通 LangChain / 精通 Prompt Engineering」——这是 2026 简历的明确雷区。
面试官看到「精通」却问不出原理，比不写更糟。

## 三、面试时最该准备的三分钟

按 `docs/面试问答.md` 的结构准备，重点是这三块：

1. **20 秒电梯陈述** —— 说清痛点（223 工具人工编排）、做法（协议栈 + 注册表 + 引擎）、结果（22/22、真实跑通）。
2. **「为什么不用 Dify/Coze」** —— 这是最容易被问到、也最能区分档次的问题。
   答法：不是"我不会用"，而是"我需要编排的是已在本机运行、各有归属的 MCP 服务，平台假设工具被托管，方向相反"。
3. **主动说 6 条短板** —— 见问答文档最后一节。能说出自己项目哪里做得不好的人，可信度远高于说不出的人。

## 四、投递建议

**这个项目适合投**：
- AI 应用开发 / 大模型应用工程师（Agent 方向）
- AI 平台工程师 / MLOps
- AI 全栈开发

**这个项目单独不够**，建议组合成三条项目线：

| 项目线 | 已有资产 | 覆盖 JD 词 |
|---|---|---|
| 工具编排与 Agent 工程 | **ai-flow**（本项目） | MCP、Tool Calling、编排、可观测 |
| 数据与检索链路 | source-gateway（25 适配器）+ 搜索引擎 MCP（27 数据源） | 检索、数据管道、多源接入 |
| 模型可用性与评测 | model-tester（三档判定防假活）+ cv-annot（标注体系） | 模型评估、评测基准、标注质量 |

三条合起来能覆盖「数据 → 标注 → 训练 → 评测 → 编排」的完整链路，这是应用层/平台层工程师的典型画像。

**注意**：YOLO26 / VGGT / SAM2 那条 CV 算法线可以作为第四个方向，但它是另一个岗位类型（视觉算法岗），
通常要求硕士 + 论文/竞赛，与应用岗不必混在同一份简历里。建议**做两份简历**。

## 五、投之前必做的三件事

1. **补业务价值数字**：选一个高频重复任务，人工与工作流各做三次，对比耗时与产出质量。
   现在只有工程指标，没有业务指标——面试官会问「这省了多少时间」。
2. **开 GitHub 仓库**：JD 明确要求「须提供 GitHub ID，我们看重 Contributions」（V2EX 义乌 AI Agent 岗原文）。
   仓库要含：README、一键启动说明、34 项自测输出、看板截图(docs/dashboard.png 已有)、架构图。
3. **写一篇复盘**：不是 README 复制，是讲「我踩了什么坑、怎么定位的、怎么改的」。
   《AgentGuide 简历编写指南》原文：面试官会问「有没有失败案例和迭代记录」。
   你手上的真实案例已经够多：pip 装 CPU 版 torch 毁掉 GPU 环境、清华镜像无 CUDA wheel、
   pip 不会自动升级已装版本、Git Bash 中文编码显示问题、MCP stdout 污染——挑 2-3 个讲透。
